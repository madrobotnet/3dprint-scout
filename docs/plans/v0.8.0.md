# v0.8.0 계획 — 스킬 내부 정리 (동작은 그대로, 지침과 코드는 줄이기)

상태: 초안 (2026-10-23). 경우님 확인 뒤 확정한다.

## 왜

0.7.0은 검증을 강하게 만들었지만 지침이 크게 늘었다. 0.7.0에서 SKILL.md와 references가 1,256줄
늘고 239줄 줄었다. 시나리오 실행 기록을 보면 늘어난 만큼 지켜지지 않는다.

- 분량: 엔진 안내까지 합치면 지침은 4,338줄이다. Blender 프로젝트 하나를 Phase 0에서 6까지 진행하면서
  실제로 읽어야 하는 분량이 3,433줄로, 전체의 79 %다(Python 경로 3,220줄).
- 같은 규칙이 여러 파일에 있다. 약 20개 규칙 묶음이 두 곳 이상에 적혀 있고, 원래 자리 밖의 사본만
  약 445줄이다.
- 사본끼리 어긋난 곳이 8개 있다(아래 A1).
- 에이전트가 자주 어긴 규칙은 대부분 읽은 파일에 있었다. 기본 모양 먼저 확인은 재실행 5개 중 3개가,
  무인 전달 첫머리는 2개 중 2개가 어겼고, 세 경우 모두 해당 파일을 다 읽었다. 문제는 읽지 않은 게
  아니라 규칙이 놓인 자리와 서로 다투는 문장이다.
- 코드도 덧붙이며 커졌다. finalize.py 2,513줄(함수 69개, check_promises 252줄, write_bundle 248줄),
  build.py 1,439줄(finish 168줄), blender_builder.py 3,117줄.

조사 근거: 시나리오 기록 14개(docs/scenarios/runs/claude/)와 지침 전체를 읽은 감사(2026-10-23).

## 원칙

1. 동작을 바꾸지 않는다. 판정, 상태, 사유 문구, CLI 옵션과 기본값, 파일 형식이 그대로다. 바꿔야
   하는 것은 A1의 결정처럼 따로 적고 경우님이 정한다.
2. 규칙마다 집이 하나다. 다른 곳에는 "무엇을 할 때 어디를 본다"는 한 줄만 남긴다.
3. 규칙은 그 일을 하는 자리에 둔다. 전달 메시지 첫머리 규칙은 전달 메시지 순서 안에, 다시 빌드한 뒤의
   확인은 다시 빌드하는 단계에 둔다. 새 규칙을 더하지 않고 자리를 옮긴다.
4. 드문 내용은 "이럴 때만 읽는다"로 뺀다. 꼭 읽기와 필요할 때 읽기를 파일 머리에서 나눈다.
5. 코드는 기계적으로 옮긴다. 옮기기 전과 후의 출력을 골든 파일로 비교하고, 로직 수정은 같은 PR에 섞지
   않는다.

## 범위

### A. 지침

**A1. 어긋난 문장 정리.** 대부분은 한쪽으로 맞추면 끝나지만 넷은 규칙을 정하는 일이라 경우님 결정이
필요하다(총괄 추천 표시).

나머지 넷(낡음의 조건 두 곳, 무인 전달 첫머리 규칙 셋의 순서, 손으로 쥐는 쓰임의 시험 출력)은 문장을
한쪽으로 맞춘다. 손으로 쥐는 쓰임은 finalize가 강제하지 않는다는 사실을 지침에 그대로 적고, 강제는
0.8.0 범위 밖으로 둔다(동작 변경).

**A2. 중복 제거.** 규칙 묶음마다 집을 정하고 사본을 한 줄 링크로 바꾼다(약 250~300줄). 큰 것부터:

|---|---|---|
| 동의와 시제품 | phase-4 "What counts as agreement" | 약 60줄 (SKILL, phase-5, phase-6, checks) |

| 약속 상태 | checks.md 상태 표 | 약 57줄 |

**A3. 드문 내용 분리.** 아래를 파일 뒤쪽 "이럴 때만" 절이나 새 참조 파일로 옮긴다(약 780~880줄이
기본 경로에서 빠짐). checks.md JSON 스키마(약 160), design.md의 드문 경우(나사, 키홀, 글자, 스냅핏
등 약 167과 기구 전용 97), blender.md의 라이브·혼합 실행(약 75~120), phase-2 프린터 스키마·두 노즐
(약 65), phase-4 스윕·strength 인자·경첩(약 65), phase-6 Bambu 파일·번들 내부(약 65), phase-5 예시
(약 50), phase-0 엔진 탐지 세부(약 50), python.md 유기 형상(48), SKILL.md 표(약 35).

**A4. 많이 어긴 규칙의 자리.** 새 규칙 없이 자리만 옮긴다.
- 무인 전달의 첫머리: phase-6 메시지 순서의 0번 항목으로.
- 바뀐 부품을 전달 전에 다시 보여 주기(재실행 5개 중 4개가 안 함): phase-5 낡음 목록의 "seen" 줄과
  phase-6 전달 전 확인에 같은 한 줄 링크.
- 사용자가 확인한 값을 나중에 말없이 바꾸지 않기(3회): phase-2 치수표 절에 이미 있는 원칙을 phase-4
  종료 확인 목록으로.

### B. 코드 (동작 그대로)

**B1. finalize.py 나누기.** `scripts/finalize.py`는 명령줄 진입점과 보고서 조립만 남기고, 같은 폴더의
모듈로 옮긴다: 근거 검사(joints, strength, measurements, seen, prints, dims), 약속 판정, 전달 대조
(3MF manifest, 필라멘트, 프리셋), 번들. 스크립트를 파일로 실행하는 방식(`python3 scripts/finalize.py`)과
`import finalize`로 테스트가 부르는 이름은 그대로 둔다(재수출).
- 골든 비교: 지금 테스트가 만드는 프로젝트와 시나리오 시작 상태 9개, 재실행 프로젝트 5개에 대해 0.7.0의
  finalize JSON을 저장하고, 나눈 뒤 바이트 비교. Windows 경로 표시도 CI에서 같은지 본다.
- check_promises(252줄)와 write_bundle(248줄)은 단계별 함수로 쪼갠다.

**B2. build.py finish() 정리.** 168줄을 검증 호출, 조립 검사, 3MF, 보고서 조립으로 나눈다. 출력 JSON
바이트 동일.

**B3. blender_builder.py는 이번에 나누지 않는다.** 생성기가 이 파일 하나를 `import blender_builder`로
쓰고 라이브 Blender 프로젝트에 사본이 놓이므로, 나누면 사본 갱신 문제가 생긴다. 죽은 코드와 중복
도우미만 정리한다(있으면).

### C. 0.7.x 후보 중 작은 것 (선택, 경우님 결정)

동작이 조금 바뀌므로 A·B와 다른 PR로 한다. 하나라도 넣으면 CHANGELOG에 동작 변경으로 적는다.
- build JSON의 STL 경로를 프로젝트 기준 상대 경로로(지금은 절대 경로).
- 에이전트가 정한 P4~P6 결정을 적을 자리(`_verify.decided` 같은 것). 지금은 finalize가 계속
  "yours to decide"로 남긴다.

손으로 쥐는 쓰임의 시험 출력 강제, P3 오탐, 상속 필라멘트 해석 같은 판정 변경은 0.8.0에서 하지 않는다.

## 0.8.0에서 하지 않는 것

- 판정 규칙 변경(위 C 제외), 새 검사, 새 엔진 기능.
- 초보자 기본 흐름(멈춤 줄이기). A가 끝난 뒤 그 위에서 따로 한다. Claude 앱 초보자 시험 결과를 보고
  정한다.
- blender_builder.py 파일 분리.

## 완료 기준

1. 목표 표의 숫자를 모두 만족한다. 읽기 분량은 감사 때와 같은 방법(단계 파일이 꼭 읽으라는 파일 +
   규칙의 집으로 이름 댄 파일)으로 다시 잰다.
2. 테스트 전부 통과(Python 3.13 + bpy 5.2.2, 3.11 + bpy 4.5.14, 3.9), CI 통과, `agentskills validate` 통과.
3. finalize, build 골든 비교가 바이트까지 같다(A1에서 정한 문구 변경이 판정 출력에 닿으면 그 차이만
   목록으로 남긴다).
4. 지침 문장 대조: 옮기거나 지운 규칙마다 새 집이 있다(0.3.1 때처럼 문장 단위 대조표, 누락 0).
5. 시나리오 9개를 Claude로 다시 돌려 0.7.0 결과와 비교, 나빠진 필수 항목이 없다. 하네스 한계(답이
   coordinator로 표시됨)는 0.7.0과 같으므로 따로 센다.

## 구현 순서 (PR 단위, main에 넣고 0.8.0에서 한 번 릴리스)

1. 이 계획(경우님 확정).
2. A1 결정 반영 + A2 중복 제거 (지침, 작성자 하나).
3. A3 드문 내용 분리 + A4 자리 옮기기 (지침, 2와 같은 작성자, 2 다음).
4. B1 finalize 나누기 + B2 build 정리 (코드, 3과 병렬 가능: 파일이 겹치지 않음). 골든 파일 먼저.
5. (선택) C.
6. 시나리오 재실행과 비교 기록, CHANGELOG, 릴리스 노트 초안.

각 PR은 작성하지 않은 쪽이 재현으로 확인한 뒤 올린다(문서는 문장 대조표, 코드는 골든 비교).
